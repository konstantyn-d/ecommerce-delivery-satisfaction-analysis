# Metric definitions

The official definition of every KPI used in this project. **Every number in the dashboard and in the deck
must map to one of these definitions.** If a figure cannot be traced to a metric on this page, it does not
go into a deliverable.

- SQL implementation: [`sql/05_kpis.sql`](../sql/05_kpis.sql) (views `model.kpi_orders` and `model.kpi_customers`)
- Baseline values: [`kpi_baseline.md`](kpi_baseline.md), generated by `notebooks/03_kpi_baseline.py`
- Field definitions used in the formulas: [`data_model.md`](data_model.md)

## 1. Rules that apply to every metric

| Rule | Meaning |
|---|---|
| Population | Orders purchased from 2017-01-01 to 2018-08-31: 99,092 orders. All order statuses are included unless the metric says otherwise. |
| Time attribution | An order belongs to the month in which it was **purchased**, also for delivery and review metrics. A late delivery in March of an order bought in February counts in February. |
| Rates are ratios of totals | A rate is *sum of numerators / sum of denominators*, never an average of per-order or per-month ratios. Monthly rates must not be averaged to get the total. |
| Missing is excluded, not zero | An order without a review is left out of satisfaction metrics; an order without a delivery date is left out of delivery metrics. It is never counted as a 0. |
| Counting orders on item-level data | On `fact_order_items` the number of orders is a distinct count of `order_id`. |
| Currency | Brazilian real (BRL), not adjusted for inflation. |

## 3. Volume and value

### 1. Number of orders

| | |
|---|---|
| Business definition | How many orders customers placed in the period, whatever happened to them afterwards. |
| Formula | `COUNT(*)` on `fact_orders` |
| Grain | order |
| Filters | none: all statuses, including canceled and undelivered orders |
| SQL column | `kpi_orders.orders` |
| Caveats | Counts orders, not customers and not items. Failed orders stay in on purpose: they are part of the problem being analysed. |

### 2. GMV (gross merchandise value)

| | |
|---|---|
| Business definition | The value of the products customers ordered, before cancellations and without freight. |
| Formula | `SUM(items_value)` on `fact_orders` (= `SUM(price)` on `fact_order_items`) |
| Grain | order (additive across any dimension) |
| Filters | orders that have item rows (98,353); the 739 orders without items contribute nothing |
| SQL column | `kpi_orders.gmv` |
| Caveats | (1) Gross: includes 360,685.65 BRL (2.66%) from orders that were never delivered. (2) It is not Olist's revenue: a marketplace earns a commission on GMV, and the commission rate is not in the data. (3) Freight is excluded. ASSUMPTION: freight is passed on to the carrier and is not merchandise value. (4) Computed from the item table, not from payments (decision #20). |

### 3. Average order value (AOV)

| | |
|---|---|
| Business definition | What a typical order is worth in products. |
| Formula | GMV / number of orders with item rows |
| Grain | order |
| Filters | orders that have item rows |
| SQL column | `kpi_orders.avg_order_value` |
| Caveats | The mean (137.68 BRL) is pulled up by a few expensive orders; the median order value is 86.90 BRL. Quote the median when describing a "typical" order. |

### 4. Freight share of order value

| | |
|---|---|
| Business definition | Out of every real the customer pays for an order (products plus shipping), how much is shipping. |
| Formula | `SUM(freight_value) / SUM(order_total)`, where `order_total = items_value + freight_value` |
| Grain | order; ratio of totals |
| Filters | orders that have item rows |
| SQL column | `kpi_orders.freight_share` |
| Caveats | A ratio of totals: expensive orders weigh more. The freight share of an individual cheap order can be far higher than 14%, which is what the customer actually experiences. For hypotheses about freight as a cause of dissatisfaction, the per-order ratio is used and labelled as such. |

## 4. Delivery

### 5. On-time delivery rate

| | |
|---|---|
| Business definition | Of the orders that reached the customer, the share that arrived on or before the date promised at purchase. |
| Formula | orders with `delivery_outcome = 'On time'` / orders with `is_delivered` |
| Grain | order |
| Filters | delivered orders with a delivery date (96,203). Excludes 2,881 not-delivered orders and 8 delivered orders without a date. |
| SQL column | `kpi_orders.on_time_rate` |
| Caveats | (1) **It flatters the service level**: an order that never arrives is not counted as late, it is simply left out. Always read it together with the not-delivered rate. (2) "On time" means "the promise was kept", not "fast". Olist's promised dates are conservative (the median order arrives 12 days before the promised date), so a high rate does not prove fast delivery. (3) Delivery on the promised calendar day counts as on time (decision #3). |

### 6. Late delivery rate

| | |
|---|---|
| Business definition | Of the orders that reached the customer, the share that arrived after the promised date. |
| Formula | orders with `delivery_outcome = 'Late'` / orders with `is_delivered` = 1 − on-time delivery rate |
| Grain | order |
| Filters | same as on-time delivery rate |
| SQL column | `kpi_orders.late_rate` |
| Caveats | Same as on-time delivery rate. This is the "problem" version of the same metric and the one used in the analysis. |

### 7. Not-delivered rate

| | |
|---|---|
| Business definition | The share of all orders that did not end as a delivery. |
| Formula | orders with `delivery_outcome = 'Not delivered'` / all orders |
| Grain | order |
| Filters | none |
| SQL column | `kpi_orders.not_delivered_rate` |
| Caveats | (1) A mixed group: canceled, product unavailable, shipped but never recorded as delivered, and orders still being processed when the data was extracted. Use `order_status` to split it. (2) For the last months of the period, some orders may simply not have arrived yet at extraction time. |

### 8. Average delay (late orders only)

| | |
|---|---|
| Business definition | When an order is late, by how many days it misses the promised date. |
| Formula | `AVG(delay_days)` over orders with `delivery_outcome = 'Late'`; the median is reported next to it |
| Grain | order |
| Filters | late orders only (6,531) |
| SQL columns | `kpi_orders.avg_delay_days_late`, `kpi_orders.median_delay_days_late` |
| Caveats | (1) Skewed: the mean (10.62 days) is well above the median (7 days) because of a few extreme delays. (2) Only late orders: averaging over all orders would give a negative number, because most orders arrive early. (3) Orders that never arrived have no delay value and are not in this metric. |

### 9. Delivery time

| | |
|---|---|
| Business definition | How many days a customer waits from purchase to delivery. |
| Formula | `MEDIAN(delivery_days)` over delivered orders; the mean is reported next to it |
| Grain | order |
| Filters | delivered orders with a delivery date (96,203) |
| SQL columns | `kpi_orders.median_delivery_days`, `kpi_orders.avg_delivery_days` |
| Caveats | Calendar days, including weekends. The median (10) is the headline figure; the mean (12.48) is inflated by long tails. |

## 5. Customer satisfaction

### 10. Average review score

| | |
|---|---|
| Business definition | The average satisfaction score customers gave to their order, from 1 (worst) to 5 (best). |
| Formula | `AVG(review_score)` over orders with a review |
| Grain | order (one score per order: the most recently answered review, decision #4) |
| Filters | orders with a review (98,330). Excludes 762 orders without a review. |
| SQL column | `kpi_orders.avg_review_score` |
| Caveats | (1) The score rates the whole order experience, not one product or one seller. (2) The distribution is not bell-shaped: 57.82% of reviews are 5 stars and 1 star (11.45%) is more common than 2 or 3 stars. A mean hides this shape, so it is always shown with the share of 1–2 star reviews. (3) Non-response is slightly higher for late orders (decision #13); the direction of the resulting bias is unknown. |

### 11. Share of 1–2 star reviews

| | |
|---|---|
| Business definition | The share of reviewed orders where the customer was clearly dissatisfied. |
| Formula | orders with `review_score <= 2` / orders with a review |
| Grain | order |
| Filters | orders with a review |
| SQL column | `kpi_orders.low_score_rate` |
| Caveats | (1) The threshold is a choice: 3 stars is treated as neutral, not as dissatisfied. (2) This is the main outcome metric of the project: it is easier to act on than a mean ("14.63% of orders end in a bad review"). (3) One review covering several orders counts once per order (decision #12). |

### 12. Share of reviews with a written comment

| | |
|---|---|
| Business definition | The share of reviews where the customer wrote a text message, not only a score. |
| Formula | orders with `has_comment` / orders with a review |
| Grain | order |
| Filters | orders with a review |
| SQL column | `kpi_orders.comment_rate` |
| Caveats | Customers who write a comment are not a random sample of customers. Any conclusion drawn from comment text (Phase 5) describes customers who chose to write, and says so. |

## 6. Customers

### 13. Repeat purchase rate

| | |
|---|---|
| Business definition | The share of customers who came back and ordered again on a later day. |
| Formula | customers with `is_repeat_customer` / all customers, where a repeat customer has orders on more than one calendar day |
| Grain | person (`customer_unique_id`), whole period only |
| Filters | customers with at least one order in the analysis period (95,774) |
| SQL column | `kpi_customers.repeat_purchase_rate` |
| Caveats | (1) Very low base: 2,129 repeat customers. Any split of this group is a small sample. (2) It understates true loyalty: a customer who first bought near the end of the period had little time to return, and purchases before 2017 or after August 2018 are not visible. (3) Several orders on the same day are one shopping occasion, not a repeat purchase (decision #32); counting them would give 3.11%. (4) Not reported by month: a monthly repeat rate depends mostly on how much time customers had to come back. |

## 7. Metrics that are deliberately not defined

| Not used | Reason |
|---|---|
| Revenue, profit, margin | Olist's commission and costs are not in the data. GMV is the only value measure available. |
| Customer lifetime value | Would need a repeat purchase rate that is reliable; see caveats of metric 13. |
| Net promoter score | The survey asks for a 1–5 satisfaction score, not a recommendation question. |
| Average delay over all orders | Negative and meaningless, because most orders arrive before the promised date. |

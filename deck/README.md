# Consulting deck

Ten slides for Olist's Head of Operations: why customers give bad reviews, where the problem sits, what
customers say, what fixing it could achieve, and what to do first.

| File | What it is |
|---|---|
| [`late_deliveries_lost_customers.pdf`](late_deliveries_lost_customers.pdf) | The deck, ready to read |
| `late_deliveries_lost_customers.pptx` | The same deck as an editable PowerPoint file, with speaker notes that name the source of every figure |
| [`build_deck.js`](build_deck.js) | Builds the PowerPoint file |
| [`deck_data.json`](deck_data.json) | Every number used on the slides (generated by `notebooks/09_deck_data.py`) |

## Storyline

Each slide title is the conclusion of the slide.

| # | Slide title |
|---|---|
| 1 | Late Deliveries, Lost Customers: why Olist customers give bad reviews, and what to fix first |
| 2 | Broken delivery promises and incomplete orders account for the avoidable bad reviews; completeness is the larger lever |
| 3 | One in seven reviewed orders ends in a bad review, although 93% of deliveries keep the promised date |
| 4 | The analysis combines 99,092 orders with 300 customer reviews read in the original Portuguese |
| 5 | A broken delivery promise is the strongest driver: 62% of late orders get a bad review, against 9% of on-time orders |
| 6 | The delay arises in transit on specific routes, above all to Rio de Janeiro and the Northeast, not with a few bad sellers |
| 7 | Late customers write "not received"; customers with several items delivered on time write "part of my order is missing" |
| 8 | Complete orders and on-time delivery in the five worst states could remove about 1,600 bad reviews, 11% of the total |
| 9 | Start with order completeness, then transit on the worst routes, and warn customers before a promise is missed |
| 10 | The findings are strong associations, not proven effects; four next steps would turn them into a business case |

## How the numbers get onto the slides

No figure is typed into a slide by hand. `notebooks/09_deck_data.py` computes every number from the data model
and the coded reviews and writes `deck_data.json`; `build_deck.js` reads that file and places the values in
titles, callouts and native PowerPoint charts. If the data changes, both steps are run again.

```
python notebooks/09_deck_data.py
cd deck
npm install
node build_deck.js
```

The PDF is exported from the PowerPoint file (File > Export > Create PDF).

Where the storyline differs from the original plan, the data decided: freight cost and price were tested and
dropped, seller concentration turned out to be weak, and incomplete orders, which were not in the plan, became
the first recommendation.
